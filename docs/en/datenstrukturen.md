# Data structures

## Raw data (raw/)

The `raw/` folder contains all input data that must be provided manually. None of it is generated by a script — it is the starting point of the data pipeline.

### raw/cluster/

This folder contains CSV files with usable floor area (m²) and usage units per building cluster, split by company buildings and residential buildings and by heat supply topology. The topologies `central`, `decentral`, and `low_temp_central` correspond to the three modeled district heating scenarios for the Adlershof quarter.

Files:

- `companies_area_and_units_per_cluster_central.csv`
- `companies_area_and_units_per_cluster_decentral.csv`
- `residents_area_and_units_per_cluster_central.csv`
- `residents_area_and_units_per_cluster_decentral.csv`
- `residents_area_and_units_per_cluster_low_temp_central.csv`

These files are the primary data basis for `get_total_area_and_units.py` and thus the starting point of the entire demand calculation.

### raw/weather/

Test reference years (TRY) from the German Weather Service (DWD) for the Berlin Adlershof location. The files are semicolon-separated CSVs and contain hourly weather data for a full year (8760 hours): surface air pressure, mean air temperature, and wind speed at 10 m height.

File names follow the scheme `try_{climate_scenario}.{period}.csv`, where the period encodes the time horizon:

- `p1` → year 2020 (near future)
- `p2` → year 2035 (mid future)
- `p3` → year 2050 (far future)

Available climate scenarios: `mean_rcp26`, `mean_rcp45`, `mean_rcp85`, `extr1_rcp85`, `extr2_rcp85`, `extr3_rcp85`. The `extr` variants represent extreme years within the RCP 8.5 scenario.

A `datapackage.json` describes the resources according to the Frictionless standard.

The weather data is used by `calc_wind_timeseries.py`, `calc_heat_waste_cop.py`, and `get_solar_thermal_profiles.py`.

### raw/wind_turbine_models/

Power curves of small wind turbines from the NREL Turbine Models dataset. The files are located in the `Distributed/` subfolder and represent turbines of the "Distributed" class (small decentralized turbines up to approx. 1 MW).

Each CSV file contains two columns: `Wind Speed [m/s]` and `Power [kW]`. The file name encodes manufacturer, model, rated power, and rotor diameter. The model `2019COE_DW100_100kW_27.6` is used as the default wind turbine in `calc_wind_timeseries.py`.

### raw/solar_thermal/

Parameter file for solar thermal collectors (`solar_thermal_parameters.csv`). Contains the technical characteristics of the modeled collectors (e.g. optical efficiency, heat transfer coefficient), used as the basis for computing hourly solar thermal yield profiles in `get_solar_thermal_profiles.py`.

### raw/wasteheat_potentials/

Waste-heat potentials for the Adlershof site from various sources:

- `Abwaermepotenzial_Adlershof_BfEE.csv` — survey by the Federal Office for Economic Affairs and Export Control (BfEE) on industrial waste-heat potentials, broken down by temperature class (high temperature HT, medium temperature MT, low temperature NT, office applications).
- `Abwärmepotenziale_Adlershof.xlsx` — additional waste-heat potentials from further sources.
- `wassertemperatur_schleuse_neukoelln.csv` — measured water temperatures at the Neukölln lock (Teltow Canal). Basis for computing the usable heat output from the Teltow Canal in `calc_waermemenge_teltowkanal.py`.

### raw/technikkatalog/

The KWW technology catalog for heat planning (as of December 2025) as a flat CSV file (`KWW-Technikkatalog-Waermeplanung_12-2025(flatdata_all).csv`). The original Excel file contains several sheets; this CSV corresponds to the exported `flatdata_all` sheet.

The technology catalog contains cost and efficiency parameters (investment costs, operating costs, efficiencies, lifetimes) for all technologies used in the energy system model. It is read by `prepare_technikkatalog.py` and transformed into the oemof-pipe input format.

## Intermediate data (datasets/)

The `datasets/` folder contains all intermediate data generated by the preprocessing scripts. It serves as input for oemof-pipe and is not edited manually. Each subfolder corresponds to one processing step of the pipeline.

### datasets/areas/

Merged usable floor area (m²) and usage units per building type and cluster, split by the three heat supply topologies (`central`, `decentral`, `low_temp_central`). The data is produced by merging the company and residential building CSVs from `raw/cluster/`. Generated by `get_total_area_and_units.py`.

### datasets/areas_forecast/

Projected usable floor area and usage units for the time horizons `statusquo`, `2035`, and `2050`, based on zoning plan growth factors. The columns contain, per time horizon, the expected usable floor area in m² and the number of usage units. This data is the basis for NPRO scenario design. Generated by `get_area_per_type_of_use_projection.py`.

### datasets/npro_buildings/

NPRO simulation results, structured in subfolders following the scheme `{year}_{climate}_{topology}/` (e.g. `2035_mean_rcp85_central/`). Each subfolder contains, per simulated building type:

- A **CSV file** with hourly profiles (8760 rows) for electricity (`plugLoadsProfile`, `emobProfile`), heat (`spaceHeatProfile`, `dhwProfile`), cooling (`spaceCoolProfile`, `processCoolProfile`), and other quantities.
- A **JSON file** with building metadata, including `buildingType` (residential/non-residential) and other NPRO configuration parameters.

The subfolders are populated by `npro run all` after `get_demands_per_building.py` has generated the scenario YAML files.

### datasets/demand_profiles/

Output of `get_demand_profiles.py`. Contains two kinds of files:

`total_demands.csv` aggregates the annual energy demand of all buildings per scenario in long format with the columns `year_climate`, `name`, and `amount`. The `name` column encodes energy carrier, topology, and building category (e.g. `heat_central-residential-demand`). This file is read by oemof-pipe as a scalar demand quantity.

`{year}_{climate}.csv` (e.g. `2035_mean_rcp85.csv`) contains normalized hourly profiles in the range \[0, 1\] for all energy carriers and topology combinations. Normalization is against the respective total annual demand. Column names follow the scheme `{energy_carrier}_{topology}-{category}`. The index is a timestamp (`timeindex`).

### datasets/wind_profiles/

Normalized hourly wind power time series, one file per TRY weather file. The file name follows the scheme `wind_timeseries-{try_filename}-{year}.csv`. Each file contains a single column `wind_profile` with values in the range \[0, 1\], normalized to the rated power of the modeled wind turbine. Generated by `calc_wind_timeseries.py`.

## Data packages (datapackages/)

The `datapackages/` folder contains the finished oemof.tabular data packages assembled by oemof-pipe from blueprint and scenario data. The structure follows the [Frictionless Data standard](https://frictionlessdata.io/).
The data packages are generated by `oemof-pipe blueprint` (template file with empty entries) and `oemof-pipe scenario` (data package per scenario):

- `datapackages/adlershof/` — base data package, generated by `oemof-pipe blueprint`. Contains all technology-independent structures.
- `datapackages/adlershof_{SCENARIO}/` — scenario-specific data package, generated by `oemof-pipe scenario`. Contains the capacities, demands, and time series adapted for the scenario.

### Directory structure

```
datapackages/{name}/
├── datapackage.json
└── data/
    ├── elements/
    │   ├── bus.csv
    │   ├── conversion.csv
    │   ├── volatile.csv
    │   ├── storages.csv
    │   ├── demands.csv
    │   ├── imports.csv
    │   ├── exports.csv
    │   ├── heatpumps.csv
    │   ├── flh_heatpumps.csv
    │   ├── backpressures.csv
    │   └── pth.csv
    └── sequences/
        ├── demands_profile.csv
        ├── volatile_profile.csv
        ├── heatpumps_profile.csv
        └── flh_heatpumps_profile.csv
```

### elements/

Each CSV file in the `elements/` folder describes an oemof.tabular component type. Each row corresponds to a component instance with scalar parameters such as capacities, efficiencies, and costs. The exact columns depend on the component type and follow the oemof.tabular convention (e.g. `carrier`, `tech`, `capacity`, `efficiency`, `marginal_cost`).

### sequences/

Hourly time series as wide CSV files with 8760 data rows (one year). Each column corresponds to the profile of one component; the column name follows the scheme `{component_name}-profile`. The sequences are loaded by oemof.tabular as the time series reference for the corresponding elements in `elements/`.

### datapackage.json

The metadata file in Frictionless format lists all resources (elements and sequences) with path, field schemas, and type. oemof-tabular reads this file when loading the data package to reconstruct the model structure.
